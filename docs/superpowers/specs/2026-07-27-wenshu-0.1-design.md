# 文枢 0.1 设计规格

## 1. 目标

文枢 0.1 是面向中文内容工作的本地 AI 工作台。首个可交付闭环是：用户在会话中上传资料、粘贴文字或链接，文枢整理并撰写文章，调用内置 Skills 生成封面与正文配图，在本地预览后，经用户明确批准，将文章保存到微信公众号草稿箱。

成功标准：

1. Linux 浏览器开发版可以完成全流程。
2. 用户通过文枢界面配置一个微信公众号的 AppID 和 AppSecret。
3. 文枢内容助手能够从聊天资料生成带 Frontmatter 的 Markdown 文章、封面和正文配图。
4. 用户能够看到公众号最终 HTML、标题、摘要、封面和图片数量。
5. 未经用户批准，不调用公众号写接口。
6. 批准后，真实公众号后台出现对应草稿，并由文枢保存包含 media_id 的本地回执。
7. AppSecret 和 access token 不进入模型上下文、会话内容、普通日志或审计参数。

## 2. 首版范围

### 2.1 包含

- 用户可见品牌改为“文枢 WenShu”。
- 首页、会话、模型配置、Skills、公众号连接、预览、审批和错误提示等核心路径中文化。
- 新增默认 Persona“文枢内容助手”。
- 保留当前 OpenAI 默认模型；其他现有模型继续可选。
- 内置精选 Baoyu 内容技能包。
- 新增微信公众号配置、预览和创建草稿能力。
- 默认隐藏 Slack、HubSpot、Jira 等非核心国外连接器，但保留其代码和测试。
- 默认关闭并隐藏 OpenWorker Cloud 登录、Gallery、托管 OAuth 和 Relay。
- 移除文枢构建中的 OpenWorker 上游自动更新端点。

### 2.2 不包含

- 微信公众号正式发布。
- 多公众号账号管理。
- 文章选题、版本、标签和发布状态等独立 CMS。
- 全界面一次性中文化。
- 删除国外连接器实现。
- 重命名 Python 包 coworker、.coworker 配置目录、COWORKER_* 环境变量、数据库文件或浏览器本地存储键。
- 自建文枢云服务、OAuth Broker、Relay 或更新服务。
- 重写 Baoyu Skills 已实现的 Markdown 渲染、图片上传和 draft/add 逻辑。

## 3. 总体架构

现有四层保持不变：

```text
文枢 React/Tauri 桌面端
        ↓
本地 FastAPI / WebSocket
        ↓
文枢内容 Persona + Skills + 权限审批
        ↓
WeChat Publisher Adapter
        ↓
Baoyu WeChat API runner → 微信公众号 API
```

职责划分：

- 文枢内容助手负责理解资料、写作、编排 Skills 和形成交付物。
- Baoyu Skills 负责 Markdown 格式、封面提示、文章配图、图像生成、公众号排版和底层草稿创建。
- Skill Pack Module 负责内置技能的发现、版本、依赖检查、归属和启停。
- WeChat Publisher Adapter 负责文枢账号配置、SecretStore、目录限制、权限审批、进程调用、输出解析、错误映射、审计脱敏和本地回执。
- 桌面端负责中文配置、预览和批准交互。

## 4. 产品配置

新增集中的产品配置 Module，向后端调用方提供小型 Interface：

- 产品名称与显示名称。
- 默认 Persona。
- 默认可见连接器集合。
- Cloud、Gallery、托管 OAuth、Relay 是否启用。
- 内置技能包集合。

前端从后端设置或健康信息获取运行时产品元数据。Tauri 的 productName、identifier、publisher、图标和更新器属于构建期元数据，仍在 Tauri 配置中明确设置，不引入跨语言动态配置机制。

文枢默认配置：

- 名称：文枢 WenShu。
- 默认 Persona：文枢内容助手。
- 默认模型：保留当前 OpenAI 默认。
- 国外连接器：代码保留、界面隐藏。
- OpenWorker Cloud 相关能力：关闭。
- 上游更新器：关闭。

## 5. 文枢内容助手

文枢内容助手复用现有 knowledge-family Agent 能力：文件、搜索、Shell、Todo、Skills、记忆、审批和会话工作区。

其系统提示明确以下流程：

1. 读取用户在聊天中上传或提供的资料。
2. 确认文章目的、受众和必要约束；已有信息充分时不重复询问。
3. 生成结构清晰的 Markdown 正文。
4. 使用 baoyu-cover-image 生成封面方案和图片。
5. 使用 baoyu-article-illustrator 分析正文并插入配图。
6. 通过 baoyu-image-gen 执行实际图像生成。
7. 调用 WeChat 预览工具生成公众号最终 HTML。
8. 展示预览并等待用户明确批准。
9. 只在批准后创建公众号草稿。

## 6. 内置技能包

### 6.1 精选范围

文枢 0.1 内置固定版本的四个 Baoyu Skills：

- baoyu-post-to-wechat
- baoyu-cover-image
- baoyu-article-illustrator
- baoyu-image-gen

不内置：

- baoyu-markdown-to-html：公众号推送脚本内部已经执行 Markdown 渲染。
- baoyu-compress-image：公众号脚本已经处理图片上传前的格式和压缩。
- baoyu-format-markdown：文枢内容助手直接生成规范 Markdown。

当前精选源码约 915 KB，体积不是发布阻碍。运行依赖包括 Bun；图像生成还依赖用户选择的图像提供商或可用的本地/CLI 后端。

### 6.2 分发与许可

Baoyu Skills 以固定版本快照作为第三方内置技能包发布，不在首次启动时从网络获取可变版本。必须保留：

- 原技能名称和版本。
- 上游来源信息。
- MIT License。
- `Copyright (c) 2026 Jim Liu`。

升级技能包必须是显式的仓库变更，并通过文枢的回归验证；运行中的同一文枢版本不得静默切换技能代码。

### 6.3 Skill Pack Module Interface

Skill Pack Module 提供：

- 枚举内置技能及版本。
- 将内置技能目录加入 SkillLoader 搜索路径。
- 报告运行依赖是否满足，例如 Bun 是否存在。
- 允许产品配置隐藏或禁用某个内置技能。
- 向界面提供来源、许可、版本和依赖状态。

用户全局 Skills 和工作区 Skills 继续按现有优先级加载。若用户安装同名 Skill，工作区版本优先于用户版本，用户版本优先于内置版本，从而允许显式覆盖而不修改发行文件。

## 7. 内容交付格式

每篇文章在会话工作区形成：

```text
articles/<slug>/
├── article.md
├── cover.png
├── images/
├── article.html
└── receipt.json
```

- `article.md` 是内容生产和公众号 Adapter 之间的主要 Interface。
- `cover.png` 和 `images/` 由生图 Skills 生成或由用户提供。
- `article.html` 由 baoyu-post-to-wechat 的 dry-run 路径生成，仅用于最终预览。
- `receipt.json` 只在成功创建草稿后由文枢写入。

Markdown Frontmatter 承载公众号元数据：

```yaml
---
title: 文枢项目介绍
author: 作者
summary: 面向中文内容工作场景的本地 AI Worker
coverImage: cover.png
sourceUrl: https://example.com
---
```

字段约束沿用 Baoyu WeChat runner 和微信公众号接口：标题必填；封面必填或由正文首图回退；摘要、作者和原文链接可选；评论选项来自账号偏好。

## 8. WeChat Publisher Adapter

### 8.1 对 Agent 的 Interface

首版暴露两个工具：

```text
wechat_prepare_draft(article_path, theme, color?, cover_path?)
wechat_create_draft(article_path, theme, color?, cover_path?)
```

`wechat_prepare_draft`：

- 只读取当前会话允许目录内的 Markdown 和图片。
- 调用 `wechat-api.ts --dry-run`。
- 生成或定位预览 HTML。
- 返回标题、作者、摘要、封面、图片数量、主题和预览文件路径。
- 不请求公众号 access token，不执行外部写操作。

`wechat_create_draft`：

- 是需要批准的外部写工具。
- 校验输入仍与已展示的预览一致。
- 从 SecretStore 读取 AppID/AppSecret。
- 通过仅对子进程生效的环境变量注入 WECHAT_APP_ID 和 WECHAT_APP_SECRET。
- 调用固定版本 `wechat-api.ts`，不拼接 Shell 字符串。
- 解析 stdout 的结构化 JSON；stderr 作为经过脱敏的诊断信息。
- 成功后保存回执并返回 media_id。

### 8.2 凭据和账号

首版只支持一个公众号账号。连接页面收集 AppID 和 AppSecret，并写入现有 SecretStore。连接检查通过公众号 token 接口验证凭据和接口可达性；错误按凭据无效、IP 白名单、权限不足、限流和网络故障分类显示。

凭据不得写入：

- 模型消息。
- Markdown Frontmatter。
- 会话数据库正文。
- Todo 或审批说明。
- 普通应用日志。
- 审计工具参数。

### 8.3 审批

调用 `wechat_create_draft` 前使用现有 Approval Card。卡片显示：

- 公众号连接名称。
- 文章标题。
- 摘要。
- 封面缩略信息。
- 正文图片数量。
- 主题和颜色。
- 操作说明“保存到公众号草稿箱，不会正式发布”。

首版不注册正式发布工具，因此 Persona 无法通过 Connector 绕过草稿箱。

### 8.4 重复提交

成功回执包含：

- 规范化 Markdown、图片和提交选项的内容哈希。
- media_id。
- 标题。
- 提交方式。
- 提交时间。
- 非敏感账号标识。

当相同内容哈希再次提交时，Adapter 返回已有成功回执，不创建重复草稿。文章正文、图片或提交选项发生变化后产生新哈希，可创建新草稿。

## 9. 数据流

```text
用户上传资料或粘贴内容
        ↓
文枢内容助手整理、撰写 article.md
        ↓
封面和文章配图 Skills 生成本地图片
        ↓
wechat_prepare_draft 调用 Baoyu dry-run
        ↓
生成 article.html 和结构化预览信息
        ↓
桌面端展示标题、摘要、HTML、封面、图片数量
        ↓
用户批准“保存到公众号草稿箱”
        ↓
wechat_create_draft 从 SecretStore 注入凭据
        ↓
Baoyu runner 上传正文图片和封面，调用 draft/add
        ↓
文枢保存 receipt.json，显示 media_id 和公众号后台入口
```

## 10. 错误和部分失败

提交前校验：

- 路径位于当前允许目录。
- Markdown 文件存在且可读取。
- 标题可解析。
- 封面存在或正文存在可用首图。
- 图片格式和大小可被 runner 处理。
- dry-run 成功且提交参数与预览一致。

提交过程中：

1. 任一正文图片上传失败则停止，不调用 draft/add。
2. 封面上传失败则停止，不调用 draft/add。
3. draft/add 失败则报告错误码和中文操作建议。
4. 已上传到素材库但公众号接口不支持回滚的图片必须在结果中说明，不宣称撤销成功。
5. 网络结果不明确时不自动盲重试 draft/add；返回“提交结果未知”，要求用户先检查草稿箱。
6. 成功 stdout 无法解析时保留经过脱敏的诊断摘要，不能凭日志文本猜测成功。

## 11. 核心中文界面

0.1 中文化：

- 应用标题、窗口标题和安装包名称。
- 默认 Persona 名称、说明和首页推荐任务。
- 会话输入、进度、交付物和模式提示。
- 模型连接核心路径。
- Skills 列表、版本、依赖状态和来源。

- 草稿成功、失败和重复提交结果。

首版复用现有会话、Artifact Preview、Approval Card、Connector 设置和会话工作区，不新增文章管理后台。

## 12. 原项目功能处理

- Slack、HubSpot、Jira 等国外连接器由产品配置默认隐藏，源码和现有测试保留。
- OpenWorker Cloud 登录入口隐藏，Cloud 客户端不在文枢默认运行路径启动。
- Gallery、托管 OAuth 和 Relay 随 Cloud 配置关闭。
- Tauri updater 不指向 OpenWorker 下载地址或公钥；0.1 开发版关闭自动更新。
- README 和运行说明改为文枢，并保留 OpenWorker 与 MIT 许可归属。
- 内部 coworker 标识首版不迁移，以维持数据和上游兼容。

## 13. 验证策略

### 13.1 后端单元测试

- 产品配置默认值和连接器可见性。
- 内置 Skill 搜索优先级、版本和依赖状态。
- 公众号凭据保存和脱敏。
- article_path 与 cover_path 的目录限制。
- dry-run 参数构造和结构化输出解析。
- 创建草稿参数构造、子进程环境变量和凭据不落日志。
- 错误码映射。
- 内容哈希和重复提交回执。
- 现有国外连接器在隐藏后仍可由非文枢配置加载。

### 13.2 Baoyu runner 合约测试

使用受控假进程或假 HTTP，不请求真实公众号：

- dry-run 成功生成预览信息。
- 正文图片先于封面和 draft/add 处理。
- JSON 成功输出可解析为 media_id。
- stderr 中凭据和 token 被脱敏。
- 非零退出、无效 JSON、超时和中断正确映射。

不重复 Baoyu Skills 自己已经覆盖的 Markdown 渲染内部细节。

### 13.3 前端测试

- 文枢品牌和核心中文文案。
- 国外连接器默认隐藏。
- 公众号 AppID/AppSecret 表单与连接状态。
- Skills 来源、版本和缺少 Bun 的提示。
- 公众号预览展示。
- Approval Card 明确说明只创建草稿。
- 成功、重复、失败和结果未知状态。

### 13.4 烟雾验证

1. 在 Linux 启动本地后端和浏览器 UI。
2. 在界面中配置真实 AppID/AppSecret。
3. 上传一组测试资料。
4. 生成测试文章、封面和至少一张正文配图。
5. 打开公众号最终 HTML 预览。
6. 批准创建草稿。
7. 在公众号后台确认草稿存在，标题、正文、图片和封面正确。
8. 确认本地 receipt.json 的 media_id 与结果一致。
9. 再次提交相同内容，确认不产生第二份草稿。

真实凭据不得进入自动化测试仓库。

## 14. 实施顺序约束

后续实施计划应按以下依赖顺序拆分：

1. 文枢产品配置和原云/更新路径关闭。
2. 可见品牌、默认 Persona 和核心中文路径。
3. 内置 Skill Pack Module 与固定版本 Baoyu 内容技能包。
4. 公众号凭据与连接页面。
5. WeChat Publisher Adapter 的 dry-run 预览。
6. 审批后的草稿创建、回执和重复提交防护。
7. 前后端自动化验证。
8. 真实公众号烟雾验证。

任何阶段都不得添加正式发布工具。
